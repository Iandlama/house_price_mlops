# House Price MLOps Pipeline

An automated MLOps pipeline that predicts house prices using the
**Ames Housing dataset**. The pipeline covers three stages — data processing, model
training, and deployment — and runs automatically every 5 minutes via
Apache Airflow.

Repository: https://github.com/Iandlama/house_price_mlops

## Pipeline overview

| Stage | What it does | Code |
|---|---|---|
| 1. Data Engineering | Loads raw data, imputes missing values, removes outliers (IQR), splits into train/test | `code/datasets/prepare.py` |
| 2. Model Engineering | Feature engineering, trains a `RandomForestRegressor`, evaluates metrics, logs to MLflow, saves the model | `code/models/train.py` |
| 3. Deployment | FastAPI service serving the model + Streamlit app, each in its own Docker container | `code/deployment/` |

All three stages are wired together into a single Apache Airflow DAG
(`services/airflow/dags/house_price_pipeline.py`), which runs
**every 5 minutes**: `prepare_data → train_model → deploy`.

## Dataset

The pipeline uses the `train.csv` file from the Kaggle competition
[House Prices — Advanced Regression Techniques](https://www.kaggle.com/competitions/house-prices-advanced-regression-techniques/data)
(1460 rows, 81 columns, price in US dollars). The file is stored in the
repository as `data/raw/housing.csv`.

The train/test split is performed by the pipeline itself
(`prepare.py`, 80/20, `random_state=42`) — the raw file is a single dataset
that has not been pre-split.

Eight features are used for prediction:

| Feature | Description |
|---|---|
| `OverallQual` | Overall material and finish quality (1–10) |
| `GrLivArea` | Above-ground living area, sq ft |
| `GarageArea` | Garage area, sq ft |
| `YearBuilt` | Year the house was built |
| `FullBath` | Number of full bathrooms |
| `LotArea` | Lot size, sq ft |
| `LotFrontage` | Linear feet of street connected to the property |
| `Fireplaces` | Number of fireplaces |

Target variable: `SalePrice` (sale price in US dollars).

## Quick start (Windows)

Requirements: Python 3.11+, Docker Desktop, Git.

```powershell
git clone https://github.com/Iandlama/house_price_mlops.git
cd house_price_mlops

python -m venv venv
.\venv\Scripts\Activate.ps1

pip install -r requirements.txt
```

The trained model (`models/model.joblib`) is already included in the
repository, so Stage 3 can be run right after cloning without repeating
Stage 1 and 2. The model can be regenerated at any time with the commands
below.

## Running the stages manually

```powershell
# Stage 1: data preparation
python code\datasets\prepare.py

# Stage 2: model training
python code\models\train.py
```

After running these:
- `data/processed/train.csv`, `data/processed/test.csv` — cleaned data;
- `models/model.joblib` — trained model (overwritten);
- console output — test metrics (RMSE, MAE, R²).

## Deployment: API and app

```powershell
docker compose -f code\deployment\docker-compose.yml up -d --build
```

- **API** (FastAPI): http://localhost:8000/docs — interactive docs,
  `POST /predict` endpoint
- **App** (Streamlit): http://localhost:8501 — a form for house parameters,
  a house illustration that updates live with the inputs, and a
  **Predict** button

Stop the containers:

```powershell
docker compose -f code\deployment\docker-compose.yml down
```

## Automation: Airflow (WSL2)

Apache Airflow does not run natively on Windows, so the pipeline is
orchestrated from **WSL2 (Ubuntu)**. Docker Desktop must be installed on
Windows with **WSL Integration** enabled (Settings → Resources →
WSL Integration → Ubuntu → Apply & Restart).

Setup (inside Ubuntu):

```bash
git clone https://github.com/Iandlama/house_price_mlops.git
cd house_price_mlops

python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
pip install apache-airflow

export AIRFLOW_HOME=~/house_price_mlops/services/airflow
```

Start Airflow:

```bash
airflow standalone
```

The admin login and password are printed to the console on first run (or
available in `services/airflow/simple_auth_manager_passwords.json.generated`).

Open the web UI at **http://localhost:8080**, find the
`house_price_pipeline` DAG, and enable it with the toggle. The DAG runs
three tasks (`prepare_data → train_model → deploy`) every **5 minutes**
on the `*/5 * * * *` schedule.

The DAG calls:
1. `python code/datasets/prepare.py`
2. `python code/models/train.py`
3. `docker compose -f code/deployment/docker-compose.yml up -d --build --force-recreate`

The `--force-recreate` flag ensures the API container is restarted with
the freshly trained model on every run.

The DAG resolves the project root automatically from its own file location
(`Path(__file__).resolve().parents[3]`), so no path needs to be edited
regardless of where the repository is cloned or which user runs it. The
only assumption is that the virtual environment is named `venv` and lives
in the project root, as set up above.

## Metrics tracking: MLflow

Parameters, metrics, and model artifacts are logged to MLflow (SQLite
backend). To view them:

```powershell
mlflow ui --backend-store-uri sqlite:///mlflow.db
```

then open http://localhost:5000.
